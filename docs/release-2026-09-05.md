The redesigned Vite frontend and structured meal-generation backend are deployed. Meal swaps, regenerate-day actions, and previous-plan reuse are outside this release.

## Changes

- Strict JSON Schema requests, response healing, model fallback routing, and server-side validation of a complete seven-day plan.
- Explicit 8,192-token output budget, disabled reasoning, a 45-second provider timeout, and a 60-second Vercel function limit.
- Truncated responses and upstream errors embedded in HTTP 200 responses are rejected before a plan can be saved.
- Shared backend code and tests moved out of `api/`; production now exposes only `api/generateMealPlan`.
- Compatible dependency updates removed the reported high and critical backend advisories.
- README updated for Vite, current deployment steps, and real deployed screenshots.

## Model configuration and limits

Production and preview use `z-ai/glm-5.2:free`, with `nvidia/nemotron-3-super-120b-a12b:free` as fallback. Both successful live checks were served by the Nvidia fallback. Earlier tests of the original Liquid/Dots pair either truncated the week or exceeded the timeout, so that pair was replaced. Free-provider availability remains variable; two successful end-to-end checks are not a reliability benchmark or service guarantee. The separate 10-run benchmark was not run because Vercel's Secret values cannot be downloaded for local use.

Nutrition targets are prompt guidance, not enforced constraints. The production test requested 2,000 kcal and 100 g protein per day, while the generated estimates averaged 1,194 kcal and 50 g protein. The release checks establish complete structured output and persistence, not accuracy or target adherence. Ingredient categories are heuristic and can also be imperfect.

The backend dependency audit retains eight moderate findings associated with `uuid` in the Firebase Admin dependency tree. Resolving these requires a separate major Firebase Admin upgrade; no forced major upgrade was included in this release.
